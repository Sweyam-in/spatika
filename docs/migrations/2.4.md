# Spatika 2.3 → 2.4 migration

2.4 is a minor release: **no export was removed and no prop was renamed.** It fixes the
stylesheet regression shipped in 2.3.0, raises contrast in every theme, repairs keyboard and
focus behaviour across overlays, and adds application components. Upgrade all four packages
together — they share one version.

```bash
npm install @spatika/tokens@2.4 @spatika/react@2.4 @spatika/charts@2.4 @spatika/editor@2.4
```

## Fixed without code changes

- **Missing utilities (2.3.0 regression).** 2.3.0 shipped without roughly 200 utility classes
  the components use — integer spacing steps, every z-index layer, `min-w-0`, `max-h-*`,
  `line-clamp-*`, `tabular-nums`, `animate-spin`, `rotate-180` and more. Spinners froze,
  accordion chevrons stopped flipping and overlays could lose their stacking. 2.4 restores them;
  a test now fails if a component uses a utility without a rule.
- **Gradient utilities** (`bg-gradient-to-*`) honour their direction and `from-` / `via-` /
  `to-` stops again instead of all drawing the same accent gradient.
- **`dark:` utilities** now apply in the Neelam and Sandhya themes.
- **Escape and outside clicks** close only the topmost overlay. Escape in a menu inside a dialog
  no longer closes the dialog.
- **DropdownMenu** items are reachable with the keyboard (they were not in 2.3).
- **Tooltips** inside dialogs render above the dialog; toasts render above modals.

## Visual changes to review

| Token | 2.3 | 2.4 | Why |
|---|---|---|---|
| `--spk-text-tertiary` (Mukta, Usha, Sandhya) | 3.9–4.4:1 on some surfaces | ≥ 4.5:1 on every surface | WCAG 1.4.3 |
| `--spk-control-border` | `--spk-border` (≈1.3:1) | derived from tertiary text (≥ 3:1) | WCAG 1.4.11 — inputs, checkboxes, radios and the switch track are visibly bounded |
| `--spk-focus` / `--spk-focus-ring` | accent at 70% | full-strength `--spk-accent-text` | ≥ 3:1 focus indicator in every theme |
| `--spk-danger` (Neelam, Sandhya) | lighter red | deeper red | White labels on destructive buttons reach 4.5:1 |
| `--spk-accent-hover` / `--spk-danger-hover` | mixed toward text colour | mixed toward black | Hover no longer lightens solid buttons in dark themes |
| `--spk-z-*` | 30 / 40 / 90 / 200 | adds select 200, menu 10000, modal 11000, toast 12000, tooltip 13000 | Mirrors `OVERLAY_Z_INDEX`, which components already used |

If you overrode `--spk-control-border` or `--spk-focus` in a custom theme, your values still
win. Custom themes made with `createTheme` pick up the new derived values automatically.

## Behaviour changes

These follow the documented (Radix-compatible) behaviour, but tests that assert the old
behaviour may need updating.

- **`Button loading`** keeps keyboard focus: it sets `aria-disabled="true"` and ignores clicks
  and form submission instead of setting the native `disabled` attribute. Tests using
  `toBeDisabled()` on a loading button should assert `aria-disabled` or `aria-busy` instead.
- **`Popover`** moves focus into its content on open and returns it to the trigger on close. To
  keep focus on the trigger (as 2.3 did), pass `onOpenAutoFocus={(e) => e.preventDefault()}` —
  Tab from the trigger still enters the popover.
- **`DropdownMenuCheckboxItem` / `DropdownMenuRadioItem`** always toggle; calling
  `event.preventDefault()` in `onSelect` now only keeps the menu open (it used to skip the toggle).
- **`FormField`** announces errors through a polite live region instead of `role="alert"`. Query
  error text by content rather than `getByRole("alert")`. `id` is now optional.
- **`Toaster`** no longer gives each non-danger toast `role="status"` — the toaster itself is the
  live region. Danger toasts keep `role="alert"`.
- **`MenuList`** inside `Menu` renders as layout (`role="none"`) instead of a second menu.
- **`Dialog`** sets `aria-describedby` only when a `DialogDescription` is rendered.

## New in 2.4

NumberInput, TagInput, OtpInput, FileUpload, Calendar, DateInput, TimeInput, DatePicker, DateRangePicker, TreeView,
DescriptionList, VirtualList, ResizablePanels, ContextMenu, ScrollArea, AspectRatio,

AlertDialog.
